1Start here

The new website is a fast, modern site. Club members edit it through two simple web pages, called portals. They never touch code.

The website

Preview address today: kiwanis-winchester.pages.dev
Final address after go-live: winvakiw.org (still the old WordPress site today; see Go-live).

Editor Portal

/editor/ — for routine updates: event photo cards, newsletter PDFs, and meeting speakers. Safe for any approved volunteer.

Admin Portal

/admin/ — for trusted administrators: page headlines and text, images, meeting details, contact info, and site settings.

Nothing is ever lost

Every save is recorded as a new version in the club's GitHub account. Any earlier version can be restored with one click (see Undo & restore).

How a change reaches the website

  1. An approved person logs in to a portal with their email (a 6-digit code is emailed to them; no passwords).
  2. They make the change and click Save & Publish (Editor) or Publish Draft (Admin).
  3. The change is saved as a new version in the club's GitHub account (the "filing cabinet").
  4. Cloudflare (the "web host") sees the new version and rebuilds the site. The change is live in about 1–2 minutes.
Important right nowStep 4 is currently disconnected (see Status, item A). Until it's reconnected, saved changes are stored safely but won't appear on the website by themselves.

3Logging in

There are no passwords. You prove who you are with a code sent to your email.

  1. Go to [website]/editor/ (routine updates) or [website]/admin/ (full site). Bookmark it; it isn't linked from the public menu on purpose.
  2. Type your email address and click Send Code. Only approved emails receive a code. Anyone else sees the same message but gets nothing.
  3. Check your inbox for "Your Kiwanis editor code". Type the 6 digits and click Log In. Codes expire after 10 minutes; just request a new one if needed.
  4. You stay logged in for about 8 hours on that browser. Click Log Out on shared computers.
Admins can use both portalsAdmins can open both /admin/ and /editor/. Editors can only open /editor/.

4Tutorial: the Editor Portal

For the everyday updates: event cards with photos, newsletter PDFs, and Wednesday meeting speakers. It can't break the rest of the site.

Add or update an event card

  1. Open the Events tab and click Add Event (top right). A new card appears.
  2. Fill in Title, Date, Category (e.g. "Community Event"), and the Details line (date, place, city).
  3. Optional: pick a Header color and paste the event's Facebook URL.
  4. Photos: click Choose File, pick a photo (JPG, PNG, WEBP or GIF), then Upload Image. Type a short caption describing the photo; this is also read aloud to blind visitors. Use the crop dropdown (e.g. "top center") if a face is cut off.
  5. Use Up/Down to reorder cards and Remove to delete one.
  6. Click Save & Publish at the bottom when finished.

Post a newsletter (The Kourier)

  1. Open Newsletters and click Add Newsletter.
  2. Enter the title (e.g. "October 2026 Kourier"), the date, and the year.
  3. Upload the PDF (PDFs only here), then Save & Publish.

Update meeting speakers

  1. Open Speakers. Edit the short introduction paragraph if needed.
  2. Under Upcoming Speakers click Add and enter date, name, organization and topic.
  3. After a speaker has presented, move them to Recent & Past Guests: add them there and remove them from Upcoming.
  4. Click Save & Publish.
Good habitsMake one batch of related changes, publish, then check the public page after a couple of minutes. The View Events Page and View Speakers links at the top open it for you.

5Tutorial: the Admin Portal

For administrators: change any page's headlines, paragraphs and images by clicking them in a live preview.

Edit text or an image by clicking it

  1. Pick a page on the left, e.g. Home Page.
  2. In the Live Preview, editable text and images are outlined. Click the one you want to change.
  3. The Selected Item box on the right shows its current value. Edit the text, or use Upload Image to replace a picture.
  4. Click Stage Change. That puts the edit into your draft, which isn't live yet. Repeat on as many pages as you like.
  5. When everything looks right, click Publish Draft (top right). All staged edits go live together.

Edit things that are hard to click

Below the preview, open Structured fields for this page. It lists every field for that page (headings, buttons, lists) as a simple form. Edit, then Stage Page, then Publish Draft.

6Undo & restore: fixing a mistake

Nothing anyone does in the portals can be permanent. Every publish is saved as a version, so you can go back. Use the simplest option that works.

Option 1 — Restore inside the portal (easiest)

  1. Editor Portal: open Save History and click Refresh. Admin Portal: select the page, then scroll to Recent saves for this file.
  2. Find the last save that was correct (each one shows who saved it and when).
  3. Click Restore on it. The portal saves a new version that matches the old one, so even the restore can be undone.
  4. Wait 1–2 minutes and check the public page.

Option 2 — Roll the whole website back (Cloudflare)

Use this if the site looks broken and you aren't sure what changed.

  1. Sign in at dash.cloudflare.com → Workers & Pages → kiwanis-winchester → Deployments.
  2. Find the last deployment from a time the site looked right.
  3. Open its ⋯ menu → Rollback to this deployment, then confirm. The whole site switches back within seconds.
Rollback is temporaryThe next publish rebuilds the site from the latest saved files. After a rollback, also use Option 1 or 3 to fix the content itself.

Option 3 — Undo a specific change in GitHub (for a web volunteer)

  1. Open github.com/Winchester-Kiwanis/kiwanis-winchester → Commits. Each portal save appears as e.g. "Editor update: events, newsletters, and speakers (name@email)".
  2. In GitHub Desktop (free app): History → right-click the bad commit → Revert changes in commit → Push origin.
  3. Cloudflare rebuilds the site from the reverted version.

7Managing who can edit

Access is controlled by two email lists stored in Cloudflare. Only people on a list can receive a login code.

List (Cloudflare setting)WhoCan open
EDITOR_ALLOWED_EMAILSVolunteers who post events, newsletters, speakers/editor/
ADMIN_ALLOWED_EMAILS2–3 trusted administrators/admin/ and /editor/

Add or remove a person

  1. Sign in at dash.cloudflare.com → Workers & Pages → kiwanis-winchester → Settings → Variables and Secrets (Production).
  2. Edit the right list. Emails are separated by commas with no spaces, e.g. president@winvakiw.org,secretary@winvakiw.org.
  3. Save, then go to Deployments and choose Retry deployment on the newest one so the change takes effect.
Clean-up itemThe editor list still contains the old demo@winvakiw.org address from the board demo. Remove it when the real emails are entered. It can no longer log in, but it shouldn't be on the list.
Use role addresses where possibleAddresses like secretary@winvakiw.org survive officer changes. When someone leaves their role, remove their personal email the same day.

8Go-live checklist

Do these in order. Steps 1–3 make editing work; step 4 makes winvakiw.org show the new site.

1. Reconnect GitHub to Cloudflare (re-enables automatic publishing)

  1. Signed in to GitHub as an owner of Winchester-Kiwanis, open github.com/apps/cloudflare-workers-and-pages → Configure.
  2. Choose the Winchester-Kiwanis organization and give it access to kiwanis-winchester (or all repositories), then save.
  3. In Cloudflare: kiwanis-winchester → Settings → Build → Git repository. Confirm it shows Winchester-Kiwanis/kiwanis-winchester. If it still shows the old owner, use Manage to reconnect it.
  4. In Variables and Secrets, set GITHUB_OWNER to Winchester-Kiwanis.
  5. Test: make any small change in a portal (or GitHub) and confirm a new entry appears under Deployments within a minute.

2. Turn on login emails (Resend)

  1. Create a free account at resend.com with a club email address.
  2. Add the domain winvakiw.org. Resend shows a few DNS records; add them where the domain's DNS is managed, then click Verify.
  3. Create an API key. In Cloudflare Variables and Secrets, add RESEND_API_KEY (type: Secret) with that key, and EDITOR_EMAIL_FROM = Kiwanis Website <website@winvakiw.org>.
  4. Retry the latest deployment, then log in to /editor/ with an approved email to confirm the code arrives.

3. Enter the real approved emails

Fill in EDITOR_ALLOWED_EMAILS and ADMIN_ALLOWED_EMAILS as described in Managing who can edit.

4. Point winvakiw.org at the new site

  1. In Cloudflare: kiwanis-winchester → Custom domains → Set up a custom domain → enter winvakiw.org, then repeat for www.winvakiw.org.
  2. Cloudflare shows the DNS record to create. Add it at the registrar where winvakiw.org is managed (today it points to the old WordPress host). If the domain's email runs through the same provider, change only the website records. Don't touch MX (email) records.
  3. Wait for Cloudflare to show the domain as Active (usually minutes, at most a day). Check winvakiw.org in a private browser window.
  4. Keep the old WordPress hosting for about a month as a safety net, then cancel it.

Run the site on your own computer

  1. Install Node.js (LTS) and Git. Then: git clone https://github.com/Winchester-Kiwanis/kiwanis-winchester.git
  2. In that folder: npm install, then npm run dev, and open http://localhost:8080.

Rehearsal mode (safe demo)

With the site running on your computer, open http://localhost:8080/admin/?demo=1 or /editor/?demo=1. Enter any email and any 6-digit code. You get the full portal with sample data, and nothing is saved or published. This only works on localhost, never on the live site.

Change history

The full history of every change is in GitHub under Commits, and a full offline copy (with history) is included in this handover folder as Website-Source/kiwanis-winchester.bundle. Restore it with git clone kiwanis-winchester.bundle kiwanis-winchester.

11FAQ & glossary

I published and the site didn't change.

Wait 2 minutes and refresh (Ctrl+F5). If it still hasn't changed, check Cloudflare → Deployments. If there's no new entry, the GitHub connection needs attention (Go-live step 1).

I didn't get a login code.

Check spam. Make sure the email is on an approved list. Codes expire after 10 minutes. If nobody receives codes, Resend needs attention (Go-live step 2).

Can two people edit at once?

Yes, but they should edit different things. If two people change the same section, the later publish wins, and the earlier one is still in the history and can be restored.

What file types can I upload?

Event photos: JPG, PNG, WEBP or GIF. Newsletters: PDF only. Keep photos under about 2 MB; phone photos can be resized first.
